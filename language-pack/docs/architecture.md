# 代码组织

GUI 与命令行共用工具预设与宝可梦准备工作；各游戏模块保留各自的通信格式与时序，共享组件则放在任何游戏目录之外。

| 位置 | 职责 |
| --- | --- |
| `pokeldn/app/` | 工具清单、参数组装、解析器检查、设置、路径与子进程 |
| `pokeldn/popup.py` | 程序在 App 中显示的[弹窗](gui.md#pop-ups)；由 `pokeldn/app/popups.py` 决定显示哪些 |
| `pokeldn/pokemon.py` | PKHeX 服务、导入、提供前的最终校验与已接收文件 |
| `pokeldn/gifts.py` | 共享的[神秘礼物文件](gifts.md)封装、读取、写入与原生转换 |
| `pokeldn/receiver_gift.py` | 交换主机端为主机存档制作的神秘礼物宝可梦（[为接收方玩家制作](gift_simulated.md#made-for-the-receiving-player)） |
| `services/pkhex/` | 固定版本的 PKHeX.Core；合法遭遇生成与兼容性检查 |
| `pokeldn/ldn/` | 无线传输、IP、Pia、可靠性与通道表 |
| `pokeldn/online/` | [在线交换](online.md)：中继、配对与加密的伙伴通道 |
| `pokeldn/gba/` | GBA 无线连接协议 |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 共享的宝可梦记录编解码器 |
| `pokeldn/<game>/` | 游戏标识、消息、状态机与协议变体 |
| `pokeldn/launcher.py` | 每个 `bin/` 启动器共用的参数（`--keys`、`--phy`、`--capture`、Linux 接口名、`--ip-host`/`--our-ip`），以及扫描到的网络的一行描述 |
| `bin/` | 解析器与会话编排 |
| `gui/` | 视图、控件、主题与开发板控制 |

App 一次只运行一个会话，因为一块开发板只服务一个进程。在另一个工具上点“开始”会停止正在运行的会话，等它退出后再启动；点“开始”也会等待正在进行的烧录结束。

## 宝可梦准备

每个交换启动器在打开无线模块之前，都会通过 PKHeX 服务准备所提供的文件。不兼容的格式、无法获取的种类以及最终不合法的记录都会被拒绝。会话的训练家身份绝不会覆盖导入宝可梦的初训家。

| 行为 | 规则 |
|---|---|
| 分析不完整 | `LegalityAnalysis.Parsed` 为 false 时重启辅助进程，并在服务锁下重试一次；再次失败则抛出异常 |
| 全新身份 | 可选启用新的 PID 与加密常数；若某记录在其下不合法，则保留它自己的，并记录 `the offer kept its own PID` |
| 异色、单一性别 | 从遭遇处请求，因此第 3 世代的 PID 保留其 RNG 关联 |
| 随机取值 | PID、个体值与野生栏位的等级，每次遭遇最多八次取值 |
| 已进化种类 | 没有遭遇能以捕获时的状态匹配时，提升到其进化等级；无性别时（脱壳忍者）采用进化后的性别，遭遇的形态不存在时（葱游兵）采用形态 0 |

在等级或种类变更后失败的记录会按顺序修复，每一步都在上一步的结果上进行；保留第一个合法的结果：

1. 仅限 HOME 的配信（《剑／盾》中的捷拉奥拉、美录梅坦）在设置为“自行生成”时会获得 HOME 追踪码（[HOME 追踪码设置](gui.md#the-home-tracker-setting)）。
2. 招式、回忆招式、TM/TR 记录标记、加强招式与精通标记，以及《传说 阿尔宙斯》的尺寸都会重新适配。
3. 已进化记录的特性会在其捕获时的栏位中刷新。此步必须在重新适配之后（《传说 Z-A》中的赛富豪）。
4. 没有经手训练家的记录会得到 `POKELDN`。
5. 以计数为基础的进化（击中要害、受到伤害、愤怒之拳使用次数、金币）从其计数开始。
6. 《晶灿钻石／明亮珍珠》中的美丽度进化（美纳斯，170）会设定该美丽度，以及其宝芬所暗示的最低光泽度。

无法满足的请求会被拒绝并说明原因。普通构建仅在以下情况失败：《晶灿钻石／明亮珍珠》中 2 种（时拉比、代欧奇希斯），《剑／盾》中 2 种（蒂安希、美录坦），《传说 Z-A》中 1 种（美纳斯，其游戏记录拒绝华丽大赛能力值），以及《朱／紫》中 31 种（仅限 HOME 的传说的宝可梦，以及 PKHeX 未提供第 9 世代进化方式的诡角鹿）。

未指定形态的请求会采用第一个能够构建的形态。仅以较晚形态存在的种类：

| 游戏 | 种类 | PKHeX 可构建的形态 |
|---|---|---|
| 剑／盾 | 基格尔德 | 10%-C、50%-C（群聚变形） |
| 剑／盾 | 玛机雅娜 | 原始之色，为配信 |
| 传说 阿尔宙斯 | 骑拉帝纳 | 起源 |
| 朱／紫 | 月月熊 | 血月 |
| 传说 Z-A | 基格尔德 | 10%-C、50%-C、完全体 |
| 传说 Z-A | 粉蝶虫、粉蝶蛹 | 花园、草甸 |
| 传说 Z-A | 彩粉蝶 | 花园、草甸、大海 |

### 遭遇顺序

构建会逐个版本尝试 PKHeX 的遭遇（`EncounterMovesetGenerator`），先尝试玩家自己的版本；在每个版本内按类别进行，每类只取前 80 个遭遇：

| 顺序 | 类别 | 由此构建的记录 |
|---|---|---|
| 1 | 野生栏位 | 在该栏位的地点和等级捕捉，可使用任何可用的精灵球 |
| 2 | 固定遭遇 | 礼物、传说的宝可梦、团体战或极巨巢穴的宝可梦 |
| 3 | 游戏内交换 | NPC 的宝可梦 |
| 4 | 蛋 | 孵化，使用其亲代遗传的精灵球 |
| 5 | 神秘礼物 | 排在所有其他类别与版本之后，因为配信的固定 PID 会使“新 PID”的提供不合法 |

《Let's Go！皮卡丘／伊布》还会在自己的版本之后尝试 GO 版本：GO Park 园区收容从 Pokemon GO 带来的宝可梦，其中包括美录坦、美录梅坦与阿罗拉形态。那里的遭遇选择是某一类 GO 遭遇（野生、团体战、调查等），覆盖 PKHeX 列出的每一个带日期的窗口。

低于其进化等级的已进化宝可梦会先在 100 级测试，然后用二分法找出最低的合法等级。《朱／紫》中的蜜集大蛇只在零散的等级上合法。

存档在收到某只宝可梦时，若其初训家的名称、ID 与性别都与自己相同，就会清除它的经手训练家（[交换写入收到记录的内容](za.md#what-the-trade-writes-into-a-received-record)）。若某个构建只有带经手训练家时才能被 PKHeX 接受（例如玛机雅娜这类 HOME 礼物），且其初训家是玩家本人，则构建时会以 POKELDN 为初训家、以玩家为经手训练家；“让我成为它的初训家”会拒绝这样的文件。

### 提供选项

构建可以指定形态、性格、特性、性别、携带道具、精灵球、亲密度、最多四个招式、个体值与努力值、某个遭遇；在《传说 阿尔宙斯》与《传说 Z-A》中还可指定是否为头目，霜奶仙的糖饰；在《剑／盾》中可指定超极巨化因子与极巨化等级；在《朱／紫》中可指定太晶属性。招式、形态、遭遇与头目会缩小遭遇搜索范围；性格、特性、性别与个体值则进入遭遇判据。当遭遇随机出别的结果时，记录会像玩家那样被修改：

| 不同之处 | 修改方式 |
|---|---|
| 性格 | 使用薄荷，第 8 世代起 |
| 特性 | 特性胶囊或特性膏药 |
| 要求为 31 的个体值 | 极限特训，需 100 级（第 7、8 世代）或 50 级（第 9 世代） |
| 形态 | 对玩家可改变形态的种类（如洛托姆）直接设定 |

携带道具、精灵球、亲密度、努力值、糖饰、超极巨化因子、极巨化等级与太晶属性都在构建之后设定，效果等同于使用极巨汤、极巨糖果与太晶碎块。糖饰是霜奶仙的形态参数，0 为草莓糖饰，6 为缎带糖饰；太晶属性是覆盖字节，星晶为 99（`TeraTypeUtil.SetTeraType`）。第 3 或第 4 世代中超过 100 的努力值需要自相遇以来获得的经验，因此记录会获得一点经验值。《传说 阿尔宙斯》的奋斗等级按游戏内显示取值，并在存储前减去个体值加成（个体值 20 起为 1，26 起为 2，31 为 3）。

亲密度属于初训家。接收方主机只有在其玩家就是初训家时才会保留该亲密度，因此“设置”中的[你的训练家](gui.md#your-trainer)必须是玩家本人；各游戏的交换页面会说明交换会改写哪些内容。《火红／叶绿》会把收到的每只非蛋宝可梦的亲密度设为 70 [trade_scene.c:1071]。

| 选项 | 列出条件 |
|---|---|
| 精灵球 | PKHeX 允许至少一个遭遇使用它 |
| 头目 | 《传说 阿尔宙斯》或《传说 Z-A》中该种类有头目遭遇（`IAlphaReadOnly.IsAlpha`） |
| 特性 | 存在携带该特性的合法构建；《传说 Z-A》不列出任何特性 |
| 携带道具 | 该游戏中已解禁的携带道具；Let's Go 与《传说 阿尔宙斯》没有 |
| 努力值 | 每项努力值 252，总和 510；Let's Go 中为觉醒值，每项 200；《传说 阿尔宙斯》中为奋斗等级，每项 10 |
| 糖饰 | 霜奶仙，且该游戏的记录保留形态参数 |
| 超极巨化 | 该种类与形态满足 `Gigantamax.CanToggle` |
| 极巨化等级 | 《剑／盾》，苍响、藏玛然特与无极汰那除外 |
| 太晶属性 | 《朱／紫》中太晶属性可变的种类（`TeraTypeUtil.CanChangeTeraType`）；18 种属性与星晶 |

个体值、努力值与亲密度标签行上的“最大”按钮会就地填满该组：六项个体值全为 31，亲密度 255。努力值会把每项能力填到上限；在总和 510 之内，该种类最高的两项种族值各得 252，第三项得剩余的 6。

### 选择遭遇

`encounters` 按[遭遇顺序](#encounter-order)列出该种类与形态的构建可能来自的每一个遭遇，并分组：同一版本、同一地点的同一类遭遇，其所有栏位与等级合为一组；或一张神秘礼物卡片（`EncounterKey`）。每组都带有其地点名称（`ILocation.GetEncounterLocation`，礼物则为卡片标题）、等级范围、相遇时的种类（若为进化前形态），以及能否为异色。给了某组键的构建只尝试该组；构建的回复会给出其 `encounter_place`。

按[遭遇顺序](#encounter-order)第一个能合法满足全部请求的遭遇会被保留；否则拒绝信息会指出第一个无法被任何遭遇满足的请求。

### Showdown 配置

“导入粘贴”使用 `ShowdownParsing.GetShowdownSets` 读取 Showdown、Smogon 或 PKHeX 配置，支持 PKHeX 导出的任何语言及其拼写。没有 `Level:` 行表示 100；`IVs:` 中缺失的个体值为 31。

| 配置中指定 | 结果 |
|---|---|
| 无法读取的行，或该游戏没有的种类、形态、特性、道具、招式，努力值超过 510 | 拒绝；不填入任何内容 |
| 《朱／紫》中的太晶属性；《剑／盾》中的超极巨化与不为 10 的极巨化等级 | 设定（[提供选项](#offer-options)） |
| 其他任何游戏中的太晶属性、超极巨化或极巨化等级，觉醒力量属性；Let's Go 或《传说 阿尔宙斯》中的努力值；《传说 Z-A》中的特性 | 略去，并附注说明 |
| 没有 `IVs:` 或 `Friendship:` 行 | 采用遭遇自身的数值 |
| 交换队列中的多个配置 | 从粘贴的选择器各做一次交换，直到队列上限；任一被拒绝则整个粘贴被拒绝 |
| 队列之外的多个配置 | 第一个填入表单 |

《剑／盾》的神秘礼物会校验 WC8 封条，并用 PKHeX 检查种类、形态、招式与道具；自制卡片属于自定义配信，而非官方活动。

### Let's Go 的连接密码

Let's Go 主机端的密码由三个位置组成，每个位置从主机选择器中的十只宝可梦选取，以三个逗号分隔的英文名称传给 `--code`。点“开始”后会等到三个都设定好才继续。

### 交换队列

在一个位置上完成多次交换的工具最多可接受六只宝可梦，按顺序提供：

| 工具 | 提供方式 | 最后一次之后 |
|---|---|---|
| 火红／叶绿 主机端与加入端 | 同行宝可梦文件，`--trades N` | 主机端拒绝（`PLAYER_CANCEL_TRADE`），并等待“取消”和“是”；加入端取消 |
| Let's Go 主机端 | `--offer`，然后 `--next-offer` | 不再应答后续交换（`pokeldn/lgpe/trade.py`） |
| Let's Go 加入端 | 重复 `--offer` | 不再应答后续交换 |
| 晶灿钻石／明亮珍珠 | 重复 `--offer` / `--trade-template` | 再次提供最后一个 |
| 传说 阿尔宙斯 | 重复 `--trade-box-record` / `--offer` | 再次提供最后一个 |
| 朱／紫 | 重复 `--trade-offer` | 不再发送消息（`pokeldn/sv/trade.py`、`done`） |
| 剑／盾 | 重复 `--offer-file` | 再次提供最后一个 |
| 传说 Z-A | 重复 `--trade-offer` | 再次提供最后一个，配合 `--fresh-pid` 使用新 PID |

每次完成的交换都会调用 `pokeldn.ldn.show_done()`，它会闪烁 LED 并打印 `[done] trade N complete`；连接阶段面板会统计该行。所有交换主机端与加入端都只在交换完成后才写入收到的宝可梦，绝不在主机提供时就写入：玩家仍可收回提供，而 App 会把每个文件存入“已接收”。N 大于 1 的交换写入输出路径时会带后缀：`_tradeN_` 加种类（火红／叶绿）、`.N`（朱／紫）、`_N`（晶灿钻石／明亮珍珠主机端）、`-N`（传说 Z-A、剑／盾）。

### 送回交换

每个交换主机端与加入端都支持 `--trade-back`（对应 App 的“送回”开关），它会在每次队列中的交换之后，再进行一次交换，提供主机刚刚送来的宝可梦，从而让通过交换进化的宝可梦在主机上完成进化。在第二次交换中，由玩家把我们的宝可梦送回。一次交换之后，主机在玩家再次交换之前不会发送任何内容（零售版《朱》的最后状态为 `b90101b902b90280800100`，随后静默 26 s，玩家退出时则离开），因此回传轮会向玩家显示一张 `trade-back` 状态卡片，提示再次交换。顺序由 `pokeldn/trade_back.py` 决定：

| 交换 | 提供内容 |
|---|---|
| 1、3、5…… | 队列中的提供 1、2、3…… |
| 2、4、6…… | 主机在上一次交换中送来的记录，逐字节一致 |

回传的记录绝不会应用 `--fresh-pid` 或任何其他提供修改。在最后一次队列交换后停止的启动器，会在两倍次数的交换后停止；重复提供最后一个的启动器则会持续交替。

| 启动器 | 记录回传方式 |
|---|---|
| 原生主机端 | `TradeBack` 代替在线伙伴（`pokeldn.online.link.Partner`）：主机在 `done` 之前的最后一次提供即为下一轮的记录 |
| 火红／叶绿 主机端与加入端 | 每个已提供的同行栏位会再次提供；TradeMons 已把收到的宝可梦放在那里 [trade_scene.c:1054-1083]。一个会话最多运行 12 次交换 |
| 原生加入端 | `Rounds` 在启动器自己的提供路径中选择每次交换的记录 |

由 `bin/frlg_trade_host.py --over-ip --trade-back` 开团的模拟法文《火红》在第 1 次交换中送出勇基拉，第 2 次交换中将其取回并进化为胡地；存档中保留了一只合法的胡地。由 `bin/swsh_host.py --ip-host --trade-back` 开团的模拟《盾》用熊徒弟换取了提供的大岩蛇，随后在第 2 次交换中用大岩蛇换回熊徒弟，并按 B 离开。

`--trade-back` 会拒绝 `--online`、为接收方玩家制作的礼物，以及团体战、巢穴与集友圈模式。“神秘礼物 - 模拟”从不提供该功能。

### 主机显示的宝可梦

`--save-shown FOLDER` 适用于每个交换主机端与加入端（对应 App“全部选项”标签页中的“保存主机画面上显示的宝可梦”开关），它会在交换过程中，主机每送来一条宝可梦记录时就将其写入，且早于任何确认。玩家中途退出时会保留该宝可梦，文件也会留下，因此可以在不交换的情况下读取某只宝可梦来做种子或合法性检查。`pokeldn.pokemon.save_shown` 会将文件命名为 `<game>-<encryption constant>.<ext>`（PK3 则为 PID）；在相同加密常数下再次送来的记录会覆盖其文件。

| 游戏 | 写入的记录 |
|---|---|
| 火红／叶绿 | 主机的整个同行队伍，三个同行区块到达后各自解密为 100 字节的 PK3；每次交换后队伍会再次发送（`pokeldn.frlg.link.trade_runtime.shown_party`） |
| Let's Go | 本轮提供类型上的每一次提供 |
| 剑／盾 | 每条携带 PK8 的宝可梦交换消息 |
| 晶灿钻石／明亮珍珠 | 每个 `NetTradePokeData` |
| 传说 阿尔宙斯 | 每条交换盒子记录，包括展示（光标）与提供 |
| 朱／紫 | 每个提供主体 |
| 传说 Z-A | 每条提供消息，包括预览（光标）与选定 |

App 会写入“已接收”文件夹旁的 `Shown` 文件夹；其中的内容不计为已收到，也不会进入银行。

### 结束一次运行

| 角色 | 结束时机 |
|---|---|
| 主机端 | 主机在至少完成一次交换后离开（`pokeldn.ldn.left_after_trade`） |
| 火红／叶绿 主机端 | 主机离开 |
| 加入端 | 主机端关闭或转交其角色；《朱／紫》《传说 阿尔宙斯》与《传说 Z-A》在一次未完成交换的位置之后会重新搜索 |

`--seconds` 与 `--hold` 用于限制主机始终不离开的运行。`--hold-after-trade N` 可用于两种角色下的每个交换启动器，它会在最后一次队列交换的 N 秒后离开该位置或关闭会话（`pokeldn.ldn.hold_after_trade_over`）。

## 本地文件与发行版

`host.local.toml`、密钥、笔记、日志与构建产物都保留在本地；没有任何生产默认值会读取 `scratchpad/`。设置与准备好的提供存放于平台的数据文件夹，可由 `POKELDN_DATA` 覆盖。清理通过 `pokeldn.app.storage` 执行（[本地存储](gui.md#local-storage)）。

打包器会打包受跟踪的运行时文件、PKHeX 可执行文件，以及适用于 ESP32、S3、C3 与 C6 的固件；缺少某个镜像会中止构建。Windows 构建会保留标准流以便记录子进程日志，同时隐藏控制台窗口。

## 验证

```sh
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```

CI 会在 Linux、macOS 与 Windows 上运行这些命令。发行版构建会对冻结后的可执行文件运行 `scripts/check_app.py`；它不需要密钥或开发板。
